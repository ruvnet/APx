# ADR 001: Accepted reference throughput with a logarithmic presentation

Status: proposed standard, implemented reference draft v0.1.

## Decision

AP is the primary throughput ratio. APx is log2(AP), its exponent. Keep task class, human cohort, tools, quality, policy, observation time, cost, and assistance mode attached to every comparison. Never derive capacity from code volume, tokens, spawned agents, or parallel runtime alone.

## Alternatives

| Choice | Delivery/runtime cost | Interpretation | Main failure |
| --- | --- | --- | --- |
| Tokens or lines per second | Low | Easy activity count | Rewards duplication, verbosity, and unusable work |
| Summed agent runtime / 8 hours | Low | Resource activity | Conflates waiting and execution with accepted human work |
| Accepted tasks per hour | Low | Direct throughput | Hides task difficulty and heterogeneous work mix |
| Accepted reference human hours per wall hour | Moderate calibration cost, low scoring cost | Cohort and task-conditioned output | Biased cohort, omitted attempts, or weak adjudication can inflate claims |

Select the fourth option and retain the third as an acceptance diagnostic. Use binary thresholded credit to keep unit meaning checkable. Keep full cost and human assistance metrics alongside speed. Use base 2 because each exponent increment means twice the accepted reference throughput; publish AP as well for ordinary readers.

## Architecture

The pure browser metrics module handles arithmetic only. Node core owns canonical hashes, frozen contract checks, gating, and paired campaign statistics. Adapters translate explicit APx receipts without pretending to satisfy native external schemas. CLI and stdio MCP validate bounded inputs and have no evaluator access to a shell, network, credentials, or external file contents.

Data lifecycle: a controlled registry should freeze the manifest before collection; external trusted runners produce complete receipts; adjudicators authenticate evidence; the scorer reads snapshots; a separate governance layer authorizes promotion and deployment. This package implements only snapshot validation and scoring. It has no registry, signing infrastructure, secret store, remote evidence reader, or production write API.

## Consequences

Calibration is more expensive than counting output, but the result corresponds to accepted reference work. Baseline quality and data integrity dominate uncertainty. Logarithms compress large ratios but do not make the result exponential intelligence. Task-conditioned reports should show the job spectrum, not average unrelated scores into a universal human replacement number.

Rollback: keep prior immutable manifests and run receipts, rerun with the previous package version, and reject promotions with regressions. No automatic deployment is performed. Any future change to thresholds, task definitions, human cohort, or cost boundaries creates a new frozen version and invalidates direct old/new comparisons unless an explicit bridge study is performed.
